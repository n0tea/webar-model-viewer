# Модели в AR

Приложение на **Vite + React + TypeScript + A-Frame (встроенный Three.js) + AR.js**. В каталоге ЭП-20 и червячный редуктор Ч-100 с анимацией сборки. Выбранная модель загружается после открытия камеры и размещается на QR-метке ТМХ `qr-full.png`. Серверная часть не требуется.

[Открыть приложение](https://n0tea.github.io/webar-model-viewer/) · [Публикации](https://github.com/n0tea/webar-model-viewer/actions)

Для сравнения доступна [версия до каталога](https://n0tea.github.io/webar-model-viewer/before-catalog/). В `public/before-catalog/` сохранены без изменений HTML, CSS, JavaScript, GLB и декодер Draco из коммита `014d663`. Vite копирует эту папку в сборку как статические файлы. Эта версия использует прежнюю загрузку A-Frame и AR.js через внешние адреса; основное приложение остаётся по корневому адресу.

## Выпуск и предварительная версия

- **Основной сайт:** https://n0tea.github.io/webar-model-viewer/ — приложение из ветки `main`, которое пользователь разрешил выпустить. Сейчас сюда перенесена версия с ЭП-20 и анимированным редуктором Ч-100.
- **Проверка разработки:** https://n0tea.github.io/webar-model-viewer/pre-release/ — предварительная версия. Новую функциональность сначала делать в `pre-release` и проверять на телефоне; затем открывать Pull Request из `pre-release` в `main` и сливать только после одобрения релиза.
- QR на карточке открывает основной сайт. Для проверки предварительной версии сначала открыть её ссылку, затем направить камеру на ту же карточку.

### Автоматическая публикация обеих веток

Активный workflow `.github/workflows/deploy.yml` установлен в обеих ветках. Копия для просмотра находится в `deployment/deploy.yml`. Он запускается при push в `main` или `pre-release`, отдельно проверяет и собирает **обе** ветки, а затем публикует их одним пакетом: `main` в корень, `pre-release` в подпапку. Поэтому разработка в предварительной ветке не переносит её код на основной сайт: основной адрес всегда собирается из `main`.

Скрипт `scripts/assemble-pages.mjs` собирает пакет. Готовые предварительные сборки в репозитории больше не хранятся — папка `/pre-release/` создаётся при публикации. Коммиты исходников можно увидеть в `/deployment.json` и `/pre-release/version.json`. Если тесты или сборка не проходят, новая публикация не выполняется, остаётся предыдущая рабочая версия.

Окружение **github-pages** разрешает публикацию веток `main` и `pre-release`. Для защиты от случайного прямого push в `main` можно дополнительно включить правило обязательного Pull Request; обязательное одобрение второго человека не нужно включать в одиночном проекте. Изменения workflow могут потребовать сохранения через сайт GitHub, поскольку у текущего входа через Git нет права `workflow`.

### Обычный цикл работы

1. `git switch pre-release`, внести изменения, сделать commit и push.
2. Дождаться успешной публикации и проверить `/pre-release/` на Android: загрузку, метку, камеру, анимацию и переключение моделей.
3. Создать Pull Request: **base `main` ← compare `pre-release`**. Пока PR не слит, основной сайт не получает новую функциональность.
4. После проверки выполнить Merge Pull Request. GitHub Actions обновит основной сайт.
5. Обновить локальные ветки и продолжать следующую задачу в `pre-release`. Не использовать force push для выпуска.

Автоматические тесты не заменяют проверку AR на реальном устройстве. Решение о переносе в `main` принимает пользователь. Прямой push в `main` тоже обновляет основной сайт, поэтому без правила защиты это соглашение команды, а не технический запрет.

## Разработка

Нужен Node.js (рекомендуется 24 LTS) с npm. В терминале VS Code, открытом в папке проекта:

```powershell
npm install
npm run dev
```

Откройте `http://localhost:5500`. Сохраняйте изменения в `src/`: Vite обновляет интерфейс. При редактировании кода во время открытой камеры страница перезагружается целиком для сброса глобального состояния AR.js. Live Server для нового проекта не нужен; если он уже занимает 5500, сначала остановите его.

Для Android по USB перенаправьте порт 5500 телефона на `127.0.0.1:5500` компьютера в Chrome DevTools или через `adb reverse tcp:5500 tcp:5500`. На телефоне откройте `http://localhost:5500`. Для опубликованного HTTPS-сайта USB и ПК не нужны.

```powershell
npm test
npm run build
npm run preview
```

`build` проверяет TypeScript и создаёт `dist/`. `preview` показывает эту сборку на `http://localhost:4173`. Тесты загрузчика проверяют отмену запросов, обработку поздней распаковки, освобождение общих ресурсов и повторную загрузку после HTTP-ошибки.

Проверка зависимостей: `npm audit --omit=dev` не обнаружила уязвимостей. Полный `npm audit` сообщает об уязвимости ReDoS в транзитивной зависимости инструментов разработки `picomatch` 4.0.7; исправленной версии в npm на момент переноса нет. Следить за обновлением Vite и его зависимостей; `npm audit fix --force` не применять автоматически. Сервер разработки по умолчанию слушает только `127.0.0.1`, инструменты сборки не входят в опубликованное приложение.

## Каталог и загрузка

Для редуктора доступны «Воспроизвести / Пауза», «С начала», ползунок времени и скорость 0,25–2×. Клип длится около 40 секунд и запускается вручную. При потере метки и закрытии камеры продвижение анимации приостанавливается. [Подробно об экспорте из Blender и повторении вручную](docs/blender-animation.md).

- `src/catalog.ts` — список моделей: уникальный `id`, название, описание, путь GLB, превью, размер файла в байтах и размер миниатюры относительно метки (`markerSpan`). Пути формируются через `assetUrl`, поэтому работают и в подпапке GitHub Pages.
- `src/components/Catalog.tsx` — карточки и выбор, доступны до запуска камеры и в AR через «Выбрать модель».
- `src/components/LoadProgress.tsx` — процент и объём скачивания, отдельная стадия распаковки, сообщение об ошибке и повторная попытка. Если сервер не сообщает размер или применяет HTTP-сжатие, показан объём и неопределённый прогресс без выдуманного процента.
- `src/ar/model-loader.ts` — загрузка только выбранного GLB через Fetch, отмена предыдущего запроса, распаковка встроенным загрузчиком Three.js из A-Frame. При переключении старая модель удаляется со сцены, освобождаются геометрия, материалы, текстуры, ImageBitmap и скелеты. Общие ресурсы освобождаются однократно. Поздний результат неотменяемой распаковки Draco тоже освобождается. Декодер используется повторно внутри одной AR-сессии.
- `src/ar/runtime.ts` — запуск A-Frame/AR.js, события метки и управление сессией; React не обновляется на каждом кадре.
- `src/ar/camera.ts` — сохранённые исправления пропорций камеры и сглаживания положения.
- `src/ar/animation.ts` — проигрыватель клипов GLB и освобождение их привязок при смене модели; `src/components/AnimationControls.tsx` — кнопки, скорость и перемотка.

Чтобы добавить модель, положите GLB со встроенными текстурами в `public/models/`, изображение в `public/previews/` и добавьте запись в `src/catalog.ts`. Карточка появится автоматически. Повторный выбор уже открытой модели не запускает лишнюю загрузку. Загрузка файлов с устройства в этом шаге не предусмотрена — выбираются модели каталога.

При закрытии камеры приложение сразу возвращается в каталог без перезагрузки страницы. Все дорожки камеры останавливаются, цикл отрисовки и отслеживание приостанавливаются. Одна текущая модель и сцена остаются в памяти: повторное открытие запрашивает только новый поток камеры, без скачивания GLB и распаковки Draco. Это сознательный обмен занятой памяти на быстрый повторный просмотр. При загрузке другой модели ресурсы предыдущей освобождаются; при закрытии вкладки или перезагрузке память всей страницы освобождает браузер. Незавершённая загрузка выбранной модели может закончиться в каталоге, чтобы подготовить её к повторному просмотру.

Проверено в браузере с имитацией камеры: три цикла закрытия/открытия сохраняют тот же объект модели и делают один запрос GLB; в каталоге все дорожки остановлены и счётчик кадров не растёт. Проверены закрытие во время первого запроса камеры, закрытие во время повторного запроса и повторный запуск после отказа в разрешении. Поведение и задержку на конкретном Android нужно дополнительно оценить на устройстве.

## GitHub Pages

Workflow `.github/workflows/deploy.yml` после push в `main` устанавливает зависимости по `package-lock.json`, запускает тесты, собирает Vite и публикует только `dist`. В **Settings → Pages → Source** должен быть выбран **GitHub Actions**. Ход публикации виден во вкладке Actions. Базовый путь Vite `./` позволяет разместить сборку в подпапке репозитория.

Каталог и превью загружаются сразу; A-Frame и AR.js загружаются при запуске AR. Зафиксированные A-Frame 1.6.0 и AR.js 3.4.7, Draco и печатная метка хранятся в `public/` и раздаются тем же хостингом. Отдельная копия Three.js не устанавливается. `@types/three` содержит только типы для TypeScript, без второго движка в браузере.

## Единая QR-метка

В основном приложении вместо Hiro используется пользовательская карточка `public/markers/qr-full.png` (2000×2000). QR внутри неё проверен декодером и открывает постоянный адрес `https://n0tea.github.io/webar-model-viewer/`. После запуска камеры AR.js отслеживает положение всей чёрной квадратной рамки и узнаёт её внутренний рисунок по `qr-full.patt`. Во время AR приложение не декодирует QR каждый кадр: QR нужен для открытия ссылки, обученный рисунок с рамкой — для положения модели. Внутри рисунка сохранена надпись ТМХ, помогающая различать ориентации.

Шаблон сформирован официальным `THREEx.ArPatternFile.encodeImage` из AR.js 3.4.7: из исходного изображения взят внутренний квадрат `(540, 540, 920, 920)`, затем записаны 16×16 значений BGR для четырёх поворотов. Внешний чёрный квадрат имеет сторону около 1840 px, поэтому `patternRatio` явно задан как `0.5`. Настройки собраны в `src/ar/marker.ts`. Если менять внутренний рисунок, положение QR или пропорции рамки, нужно заново создать `.patt` и проверить распознавание. Изображение пользователя не перерисовывалось.

Напечатайте карточку целиком, с белым полем, без растягивания по одной оси. Сначала отсканируйте QR камерой телефона для входа на сайт; затем откройте камеру приложения и держите всю рамку в кадре. Если карточка открыта на самом телефоне, для AR понадобится распечатка или второй экран. Старая версия `/before-catalog/` по-прежнему использует Hiro.

## Модель и отслеживание

Страница привязывает миниатюру электровоза ЭП-20 к QR-метке ТМХ с помощью A-Frame и AR.js. Модель преобразована из предоставленного FBX через Blender. Текстуры включены в GLB. Исходный экспорт `ep20.glb` занимает 48,2 МБ. Для показа используется `ep20-mobile.glb` размером 9,1 МБ с текстурами до 1024 пикселей и геометрией, сжатой Draco. В обеих версиях около 252 тысяч треугольников. Экспортирована статическая поза модели, детали сохранены отдельными объектами. Подключены карты материалов из папки «Текстуры», включая отсутствовавшие в FBX привязки Details и карту шероховатости Wheels.



Трекер и 3D-слой используют пропорции фактического видеопотока. Параметры камеры формируются для этого разрешения с квадратными пикселями и приближённым фокусным расстоянием. Это общая модель оптики, точная калибровка конкретного телефона не выполнялась. Матричное сглаживание AR.js отключено. Компонент `smooth-marker-pose` отдельно сглаживает положение и поворот, сохраняя единичный масштаб метки. Распознавание ограничено 30 измерениями в секунду, разрешение 3D-слоя — 1280 пикселями по длинной стороне с плотностью до 1,5. Его положение обновляется при отрисовке между измерениями. Размеры элементов пересчитываются при изменении окна или видеопотока.

## Планы развития

- Проверить печатную QR-метку на разных Android-устройствах, при разном освещении, размерах печати и углах; сравнить устойчивость с Hiro. По результатам при необходимости улучшить макет и повторно обучить шаблон.
- Сохранить AR.js основным трекером текущей версии. Провести сравнительный тест с MindAR, 8th Wall Image Targets и, при подходящих условиях лицензирования, Zappar Universal AR. Проверять подходящие каждому трекеру печатные цели одинакового физического размера, одну модель, одинаковое освещение и расстояния. Отдельно фиксировать различия макетов и настроек.
- В сравнении измерять время первого обнаружения, дрожание неподвижной модели, работу под углом, восстановление после потери метки, FPS и нагрузку при продолжительной работе. Проверить Pixel 6 и другие Android-устройства в Chrome, Samsung Internet и Firefox. Результат сравнения использовать для выбора трекера следующей версии.
- При появлении сложных взаимодействий с деталями, разборки или управления анимациями оценить переход с A-Frame на прямой Three.js. Каталог и загрузчик уже отделены от интерфейса и трекера; сам переход не гарантирует повышения FPS.
